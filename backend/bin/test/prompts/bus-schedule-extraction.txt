SPECIAL IMAGE TYPES TO HANDLE:
1. **LOW CONTRAST/FADED BOARDS**: Many old bus boards have faded paint or weathered text
   - Extract what you can read, use best interpretation for unclear characters
   - Pay attention to Tamil script which may be more legible than English

2. **HANDWRITTEN/HAND-PAINTED BOARDS**: Common in rural areas
   - Numbers may be stylized or unclear
   - Focus on extracting times and locations even if fonts are non-standard

3. **ROTARY/SPONSOR BOARDS**: Boards with logos (Rotary International, Lions Club, etc.)
   - Ignore sponsor logos, focus on bus schedule content
   - Header may have organization name alongside station name

4. **PRIVATE BUS SERVICE POSTERS**: Colorful marketing posters with service details
   - Look for bus operator name, service number (e.g., TN30BEM1040)
   - Extract "VIA" information showing intermediate stops
   - Handle bold departure times in table format
   - May show fare information (ignore fares, focus on timings)

5. **PASS/CITY BUS SCHEDULES**: Sequential numbering with departure times
   - Format: numbered list (1, 2, 3...) with times
   - Each number = one departure time
   - Origin and destination shown at top/header

6. **DENSE TIME TABLES**: Multiple columns of times (point-to-point schedules)
   - Each column may represent different time periods (AM, afternoon, PM, night)
   - Extract ALL times, reading left-to-right, top-to-bottom
   - May have PP (post-midnight) or special indicators

7. **VOLVO/LUXURY BUS ALLOCATION**: Tables with chassis numbers, depot info
   - Focus on route number, origin, destination columns
   - Ignore technical details (chassis numbers, FC due dates)
   - Extract only schedule-relevant information

8. **TEXT-BASED SOCIAL MEDIA POSTS**: Bus schedules shared as text
   - Common format: "HH:MM AM/PM BusNumber Destination (via/type)"
   - Parse line by line, extracting time, bus number, destination
   - Handle Unicode Tamil text and English mixed content

OUTPUT FORMAT (strict - no markdown, no explanation):

🚨 CRITICAL - ORIGIN LINE RULES:
The ORIGIN line MUST contain the EXACT station name from the board header/title.
- Look at the TOP of the bus board image - the largest, most prominent text
- This is typically the bus stand name (e.g., "ERODE", "SALEM", "CHENNAI", "COIMBATORE")
- Extract the EXACT name as shown - do not use placeholder words
- NEVER write "ORIGIN:ORIGIN" or "ORIGIN:STATION" or "ORIGIN:BUS STAND"
- ALWAYS extract the actual city/town name
- If you cannot clearly read the header, look for "FROM:", "DEPARTURES FROM:", or similar text
- Example: If header says "ERODE BUS STAND", write "ORIGIN:ERODE"
- Example: If header says "SALEM", write "ORIGIN:SALEM"
- Example: If header says "தமிழ்நாடு அரசு போக்குவரத்துக் கழகம் (கோவை) லிட் ஈரோடு மண்டலம்", write "ORIGIN:ERODE"

COMMON MISTAKE TO AVOID:
❌ WRONG: If board header shows "ERODE மண்டலம்" and lists destinations "கூடலூர், ஊட்டி, மேட்டுப்பாளையம்"
  DO NOT write "ORIGIN:GUDALUR" (that's a destination, not the origin!)
✅ CORRECT: Write "ORIGIN:ERODE" (that's the station in the header)

The origin is WHERE THE BUS DEPARTS FROM (shown at top), not where it's going to (shown below).

🚨 CRITICAL - BIDIRECTIONAL ROUTE DETECTION:
MUST check for bidirectional indicators in the image/text:
- Visual indicators: ⇄, ↔, ←→, ⟷, ↕, or two opposite arrows
- Text indicators (English): "bidirectional", "both ways", "two-way", "return service", "both directions"
- Text indicators (Tamil): "இருவழி" (iruvazhi), "இரு திசை" (iru thisai), "மீண்டும்" (meendum - return)
- Layout indicators: Two columns with opposite direction headers (e.g., "A → B" | "B → A")
- "NON-STOP" or "சூட்" services with two columns of times typically indicate bidirectional

WHEN BIDIRECTIONAL DETECTED:
1. Add "BIDIRECTIONAL:true" line after TYPE line
2. Extract routes for BOTH directions:
   - Forward direction: from origin to destination
   - Reverse direction: from destination back to origin
3. If times shown for both directions, use the respective times
4. If only one set of times shown, duplicate for reverse direction
5. Create separate route entries for each direction

STOP-LEVEL TIMING FORMAT (optional, included in stops_data field):
If image shows DETAILED STOP TIMINGS (arrival and departure at each stop), use this format in the last field:
STOPS:[stop1@arr1-dep1,stop2@arr2-dep2,stop3@arr3-dep3,...]
Example: STOPS:[Sirkazhi NBS@01:10-01:15,Chidambaram BS@01:50-02:02,Vadalur@02:57-,Panruti Arch@03:40-]
Use - for missing times (e.g., 02:57- means arrival at 02:57, no separate departure shown)
If only name shown, use format like: stop_name@ (with no times)

FIELD RULES:
- bus_num: Route number exactly as shown (e.g., 166UD, 42A, 520, T.N.01, etc.) OR - if no number
- from_location: 🚨 CRITICAL - Must be CLEAN city/station name ONLY
  * MUST REMOVE: Bus numbers (27D, 42A), keywords (from, to, departure, arrival, at, via, through)
  * Extract ONLY the city name (e.g., "27D from Chennai" → Chennai, NOT "D from Chennai")
  * Extract ONLY the city name (e.g., "Madurai Departure" → Madurai, NOT "Madurai Departure")
  * CRITICAL: Remove trailing/leading fragments of bus numbers
    - "123A Coimbatore" → from_location=Coimbatore (NOT "A Coimbatore")
    - "27D, Chennai" → from_location=Chennai (NOT "D Chennai" or "D, Chennai")
    - "Route 42 Salem" → from_location=Salem (NOT "42 Salem" or "Route Salem")
  * For destination_table boards: ALWAYS use the ORIGIN station (from "ORIGIN:" line)
  * NEVER use "ORIGIN", "FROM", "STATION", or generic placeholders
  * NEVER use destination names as the origin
  * CRITICAL: Clean the extracted text by removing keywords: "from", "to", "departure", "arrival", "at", "via", "through", "reaching", "leaving"
  * Example: If ORIGIN:ERODE, then from_location MUST be "ERODE" for all routes
  * Example: If ORIGIN:SALEM, then from_location MUST be "SALEM" for all routes
- to_location: 🚨 CRITICAL - Must be CLEAN city/station name ONLY
  * Extract ONLY the city/destination name
  * MUST REMOVE: Keywords (departure, arrival, at, via, through, reaching, route)
  * Example: "Madurai Departure" → Madurai (remove "Departure")
  * Example: "to Trichy at 6 PM" → Trichy (remove "to", "at", "6 PM")
  * Example: "Route Coimbatore" → Coimbatore (remove "Route")
  * Example: "Salem via Dharmapuri" → Salem (remove "via", keep destination only)
  * NEVER include time or direction keywords in location name
  * NEVER include bus number fragments (e.g., if "123A Madurai", to_location is Madurai, NOT "A Madurai")
  * Final destination in English (REQUIRED - never leave blank)
- dep_time: Departure time(s) from origin in HH:MM 24-hour format, comma-separated for multiple times
- arr_time: Arrival time(s) at destination in HH:MM format (use - if not shown)
- bus_type: Bus category (EXPRESS, DELUXE, ORDINARY, SUPER DELUXE, AC, ULTRA DELUXE, MUFSAL, TOWN, etc.) or - if not shown
- stops_data: Either comma-separated stop names (old format), OR detailed STOPS:[...] format with per-stop timings

TIME EXTRACTION RULES:
- Convert 12-hour to 24-hour format (6:00 AM → 06:00, 6:00 PM → 18:00)
- If time shows seconds (19:41:00), output as HH:MM only (19:41)
- Tamil time indicators: காலை = AM, மாலை/இரவு = PM
- Extract ALL times shown for each route, comma-separated for MULTIPLE BUSES
- Handle both 12-hour format (3:25PM) and 24-hour format

CRITICAL FOR DEPARTURE-ONLY TIMES:
- When a board shows ONLY departure times (no arrival times shown):
  * Each time = ONE departure for ONE bus schedule
  * Use "-" for arrival time field (means "not shown on board")
  * DO NOT assume or calculate arrival times
  * DO NOT use journey duration to estimate arrival
- Example from image (departure times only):
  TIME 1: "07:45" = Route: Hosur→Chennai, dep_time=07:45, arr_time=- (not shown)
  TIME 2: "14:30" = Route: Hosur→Chennai, dep_time=14:30, arr_time=- (not shown)
  TIME 3: "17:00" = Route: Hosur→Chennai, dep_time=17:00, arr_time=- (not shown)
- Create 3 separate extraction entries (one for each departure time)
- Do NOT merge times: dep_time=07:45,14:30,17:00 with arr_time=-
  Instead: Create 3 separate routes with individual departure times

- For stop-level timings: capture BOTH arrival and departure at each intermediate stop
- If only one time shown at a stop (common for through routes), use format: time- (arrival only) or -time (departure only)
- CRITICAL: Do NOT append stop names to comma-separated times!
  Wrong: "06:00,07:05,09:15,10:20Sathyamangalam"
  Correct: dep_time=06:00,07:05,09:15,10:20 and stops_data=Sathyamangalam (or STOPS:[...] format)

2. **HANDLE ALL IMAGE QUALITIES**: Work with faded, handwritten, low-contrast, or weathered boards
   - Use context clues from readable portions to infer unclear text
   - Tamil script may be more legible than English on old boards

   - VIA routes clearly marked (e.g., "Via: Dharmapuri, Kaveripattinam")

   - Each number = one departure slot
   - Extract in sequential order preserving the timing sequence
5. **MULTI-COLUMN TIME GRIDS**: Dense tables with many time columns
   - Read systematically: left-to-right, then top-to-bottom
   - Each cell = one departure time
   - Watch for column headers indicating AM/PM or time periods
6. **SOCIAL MEDIA TEXT SCHEDULES**: Plain text format (common on Facebook/WhatsApp)
   - Parse each line as: TIME BUSNUMBER DESTINATION (ADDITIONAL INFO)
   - Handle mixed Tamil/English Unicode text
   - Extract operator mentions (e.g., "TNSTC-410M", "RSMANI-1")
7. **TECHNICAL ALLOCATION TABLES**: Tables with depot/chassis info
   - Focus ONLY on: bus number, route, origin, destination
   - Ignore: chassis numbers, FC dates, depot codes (unless part of route ID)
8. If image shows DETAILED STOP TIMINGS (each intermediate stop has arrival and/or departure time):
   - MUST use the STOPS:[...] format in the last field with per-stop timing
   - Example: STOPS:[Sirkazhi NBS@01:10-01:15,Chidambaram BS@01:50-02:02]
   - This is MORE IMPORTANT than simple via lists
9. If you see a destination board pattern (header + multiple destination rows), use the ACTUAL ORIGIN STATION NAME (from header) in from_location field, NOT the word "ORIGIN"
10. If you see a BIDIRECTIONAL route pattern (A ↔ B with two time columns), extract as TWO separate routes:
   - First route: A → B with times from left column
   - Second route: B → A with times from right column
11. If you see DASH FORMAT routes (A-B notation), parse the dash to extract FROM and TO locations:
   - "ORIGIN-DESTINATION" means FROM ORIGIN TO DESTINATION
   - Extract as a single route with the parsed origin and destination

14. If you cannot read a field clearly, use your best interpretation

    - This is stop-level timing information that MUST be captured in STOPS:[...] format
    - Do NOT lose this information by only listing stop names in the via field
    - Format each stop as: stopName@arrivalTime-departureTime
    - Use - for missing times (e.g., @02:57- means arrival at 02:57, no departure shown)
21. MULTIPLE SERVICES PER DAY: If same route appears with different times, extract as separate routes
22. SPECIAL STOPS (toll gates, fuel stops, breaks): Include with format: STOPS:[...,Toll Gate@time-,...] or Tea Break@04:20-04:35
23. ROUTE VARIANTS: If board shows "166-Exp" vs "166-Local", extract each variant as separate route
24. REVERSE DIRECTION: If board shows A→B and B→A, extract as TWO routes with swapped origin/destination
25. DURATION-BASED: If "Duration: 6h 30m" shown instead of arrival, leave arr_time as dash
26. MULTIPLE TABLES: Extract from all visible sections (Daily, Holiday, Weekend schedules)
27. POOR QUALITY: For faded/overlapping text, use best interpretation; prioritize handwritten over printed if clearer
28. FARE/CATEGORY INFO: Only extract if in separate time columns, not for fares alone
29. **BUS OPERATOR NAMES**: Common operators include TNSTC, SETC, Private operators (capture in context if shown)
30. **EXPRESS/NON-STOP SERVICES**: Clearly marked services should have bus_type set appropriately
31. **VIA STOPS**: When "Via:" or "வழி:" is shown with stop names, capture in stops_data field
